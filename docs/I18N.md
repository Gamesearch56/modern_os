# Internationalization

Every user-visible string goes through `I18n.t("path.to.key")`. There is
no `qsTr()` in this environment (Quickshell does not wire Qt Linguist —
`docs/DECISIONS.md` #4).

## Files

| File | Role |
|------|------|
| `stow/modern/.config/modern/translations/en.json` | English (also fallback) |
| `stow/modern/.config/modern/translations/de.json` | German |
| `stow/shell/.config/quickshell/modern/Commons/I18n.qml` | reactive singleton |
| `install/lib/i18n.sh` | same keys for installer / scripts |

Add a key to **both** JSON files in the same change, same nested path.
`scripts/lint-layers.sh` fails if the key sets differ.

## Lookup

```
I18n.t("bar.volume")
I18n.t("bluetooth.connected", { count: 2 })   // "{count} connected"
```

`config.json` → `language.ui` selects the active file;
`language.fallback` (default `en`) is always loaded so a missing German
string still renders English instead of the raw key.

The function is named `t()`, not `tr()` — `QtObject` already inherits a
Linguist `tr()` that would shadow a custom function.

## QML rule

Never put a bare string in a `Text` / `MText` binding. Use `MText { key:
"…" }` or `MText { value: I18n.t("…", params) }` for interpolated /
dynamic strings (clocks, counts).

## New key checklist

1. `en.json` and `de.json`, same path
2. Reference `I18n.t("that.path")` or `key: "that.path"`
3. `scripts/lint-layers.sh`
